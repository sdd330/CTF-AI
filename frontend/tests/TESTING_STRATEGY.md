# 前端测试策略

## 测试金字塔

```
       /\
      /E2E\          <- 复杂场景、集成测试
     /------\
    /  集成  \        <- 多组件协作
   /----------\
  /   单元测试  \     <- 基本功能、边界条件
 /--------------\
```

## 单元测试（Vitest）

### 原则
- **快速**：每个测试 < 100ms
- **简单**：只测试基本功能和边界条件
- **隔离**：使用 mock，不依赖外部服务
- **OOP**：使用公共接口访问，避免 `as any`

### SocketManager 单元测试范围
✅ **应该测试**：
- 单例模式
- 连接/断开基本操作
- 事件订阅/取消订阅
- 连接状态查询

❌ **不应该测试**（留给 E2E）：
- 复杂消息格式验证
- 完整游戏流程
- 重连机制
- 超时处理
- 并发消息处理

### PhysicsManager 单元测试范围
✅ **应该测试**：
- 基本碰撞检测逻辑
- 单个碰撞事件处理
- 位置查找算法

❌ **不应该测试**（留给 E2E）：
- 完整游戏场景模拟
- 多重碰撞同时发生
- 性能测试

### 测试文件命名
- 基本功能：`*.test.ts`
- 集成测试：`*.integration.test.ts`
- 性能测试：`*.perf.test.ts`

## E2E 测试（Playwright）

### 原则
- **真实**：使用真实服务器和网络
- **完整**：测试完整用户流程
- **慢但可靠**：可以运行较长时间

### SocketManager E2E 测试场景
1. **消息格式一致性**
   - init/status/finished 消息格式
   - 与 backend 协议对齐

2. **完整游戏会话**
   - 连接 → 初始化 → 游戏循环 → 结束
   - 多轮游戏

3. **异常场景**
   - 网络断线重连
   - 服务器崩溃恢复
   - 消息丢失重传

4. **性能测试**
   - 60fps 消息发送
   - 并发连接
   - 内存泄漏

### 测试文件位置
```
frontend/tests/e2e/
├── game-session.spec.ts      # 完整游戏会话
├── socket-protocol.spec.ts   # 消息格式验证
├── error-handling.spec.ts    # 异常处理
└── performance.spec.ts        # 性能测试
```

## 运行测试

```bash
# 单元测试（快速）
pnpm test

# E2E 测试（慢但完整）
pnpm test:e2e

# 带 UI 的 E2E 测试
pnpm test:e2e:headed

# 调试模式
pnpm test:e2e:debug
```

## 测试覆盖率目标

- **单元测试**：80%+ 代码覆盖率
- **E2E 测试**：100% 关键路径覆盖
- **总体**：90%+ 覆盖率

## 避免的反模式

❌ **不要在单元测试中**：
- 使用真实 WebSocket
- 测试完整游戏流程
- 测试多组件集成
- 使用 `setTimeout` 模拟异步
- 使用 `as any` 绕过类型检查

✅ **应该**：
- 使用 mock WebSocket
- 测试单个方法的行为
- 使用 OOP 公共接口
- 使用 `async/await` + `Promise.resolve()`
- 保持测试简单明了
